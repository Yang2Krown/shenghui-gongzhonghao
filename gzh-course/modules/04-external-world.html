微信公众号 API：最后一公里

文章写好后，需要推送到你的微信公众号草稿箱。系统直接调用微信的官方 API，不需要你手动复制粘贴。

Python async def get_access_token(appid: str, secret: str) -> str: """获取微信公众号 access_token""" url = to_ipv4_url(f"{WECHAT_API_BASE}/token") params = { "grant_type": "client_credential", "appid": appid, "secret": secret, } async with wechat_client(timeout=15) as client: resp = await client.get(url, params=params) resp.raise_for_status() data = resp.json() if "access_token" not in data: raise ValueError(f"获取失败: {data}") return data["access_token"]
English
第 1 行：定义一个异步函数，输入 appid 和 secret（微信公众号的账号密码），输出 access_token（临时通行证）
第 3 行：to_ipv4_url() —— 强制使用 IPv4。为什么？因为微信 API 的 DNS 有时会解析到 IPv6，而服务器可能不支持 IPv6
第 4-8 行：构造请求参数——grant_type 表示"我要用账号密码换 token"
第 9-11 行：发送 GET 请求，15 秒超时
第 13-16 行：检查返回结果——如果没有 access_token，说明失败了，抛出错误
⚠️
微信 API 的两个坑

坑 1：微信 API 的 DNS 有时会解析到 IPv6 地址，但服务器可能不支持 IPv6。所以代码强制用 to_ipv4_url() 转换成 IPv4 地址。

坑 2：微信 API 默认会把中文转义成 Unicode 编码（如 你好），导致解析失败。所以代码用 ensure_ascii=False 保持中文原文。

Redis + Celery：后台任务队列

爬虫和 AI 流水线都很耗时——可能需要几分钟甚至更久。如果让用户一直等着，体验会很差。

📮
邮局比喻

想象你去邮局寄包裹。你把包裹交给柜台（提交任务），然后就可以走了（不用等）。邮局会安排分拣员（Celery Worker）处理你的包裹。你随时可以来查进度（轮询 Progress API）。Redis 就是那个"待处理包裹架"——所有任务先放在这里，分拣员按顺序取走处理。

⚡

Redis

内存数据库，速度极快。在这里充当"消息队列"——存放待处理的任务。也用于缓存和会话管理。

🔄

Celery

分布式任务队列。接收任务 → 放入 Redis → Worker 取出执行。支持定时任务（Beat）、重试、超时等。

📊

Progress API

前端通过轮询 /progress 接口获取任务进度。每个 Agent 完成后更新进度，前端实时显示"正在执行 Agent A..."

PostgreSQL + pgvector：不只是存数据

系统用 PostgreSQL 存储所有数据，但不只是简单的增删改查——它还用 pgvector 做语义搜索。

Python # SQLAlchemy 的 JSON 多态：同一字段在不同数据库用不同存储 JSONField = JSON().with_variant(JSONB(), "postgresql") # 自动回退：没有 PostgreSQL 就用 SQLite if not settings.POSTGRES_PASSWORD: DATABASE_URL = "sqlite+aiosqlite:///./sql_app.db" else: DATABASE_URL = f"postgresql+asyncpg://..."
English
第 2 行：JSON 多态——同一个字段，PostgreSQL 用 JSONB（支持索引和搜索），SQLite 用普通 JSON
第 5-8 行：自动回退——如果没有配置 PostgreSQL 密码，就用 SQLite。这让本地开发零配置，生产环境用完整功能
好处：开发者在本地用 SQLite 快速开发，部署到服务器时自动切换到 PostgreSQL + pgvector，代码不用改
🔍
为什么需要向量数据库？

普通数据库只能精确匹配——"标题包含'GPT'"。但语义搜索需要理解意思——"讨论大语言模型的文章"应该匹配到包含 GPT、Claude、LLaMA 等关键词的文章。pgvector 让 PostgreSQL 具备了这种能力。
