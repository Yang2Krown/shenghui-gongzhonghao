认识主角们

系统里有 4 条主要的 AI 流水线，每条流水线由多个 Agent 组成。认识它们，你就能指挥 AI 做更多事

多 Agent 流水线：AI 的团队协作模式

你可能用过 ChatGPT——一个 AI 对话框，问什么答什么。但这个系统用的是完全不同的模式：多个 AI 角色按顺序协作。

🏭
工厂流水线比喻

想象一个汽车工厂。一辆车不是一个人从头造到尾——而是经过冲压、焊接、涂装、总装等工位，每个工位的工人只做一件事。这个系统的 AI 流水线也一样：Agent A 产出半成品，Agent B 审核，Agent C 挑刺，Agent D 做最终决定。

⛏️

创造 → 评分 → 预测点击率 → 最终裁判

爬虫适配器：13 个信息源各司其职

系统从 13 个不同的平台抓取信息。每个平台的网页结构都不一样——有的用 RSS，有的需要爬网页，有的需要模拟浏览器。

🔌
适配器模式（Adapter Pattern）

就像一个万能充电器——一个充电头可以适配苹果、安卓、Type-C 等各种接口。系统用一个统一的接口（SourceAdapter）来处理所有信息源，每个适配器只需要实现自己的抓取逻辑。

📡
RSS 适配器

最传统的方式——订阅博客、新闻网站的 RSS 源，自动获取新文章

🐙
GitHub Trending

追踪 GitHub 上最火的开源项目，发现技术趋势

🔥
Hacker News / Reddit / V2EX

技术社区的热门讨论， often 是技术趋势的风向标

💬
微信搜索（Exa + 搜狗）

直接搜索微信公众号文章，获取竞品内容

🐦
Playwright X（推特）

用浏览器自动化抓取推特内容，因为推特没有公开 API

LLM 抽象层：4 个 AI 大脑各有所长

系统不只用一个 AI 模型——它根据任务特点选择最合适的模型。这就像一个公司有不同专长的员工：有的擅长创意，有的擅长分析，有的性价比高。

Python class LLMClient(ABC): """所有 LLM provider 实现此接口。""" provider: str = "" default_model: str = "" @abstractmethod async def chat( self, messages: List[ChatMessage], *, model: Optional[str] = None, temperature: float = 0.3, max_tokens: int = 4096, json_mode: bool = False, ) -> ChatResult: """通用 chat 接口。"""
English
第 1-2 行：定义一个"万能充电器"接口——所有 AI 提供商都必须实现这个标准
第 4-5 行：记录两件事：这个 AI 是谁（provider），默认用哪个型号（default_model）
第 7-14 行：核心方法 chat()——不管底层是 DeepSeek 还是 Claude，调用方式完全一样
第 16-17 行：json_mode 参数——告诉 AI "请输出 JSON 格式"，这样代码就能直接解析
💰

DeepSeek

便宜够用。负责预处理阶段的信息提取——从原始资讯中提取信息类型、关键要素、方向判断。

🧠

Claude

最强创意能力。负责选题挖掘的 Agent A/B——4 Persona 评议、6 维度评分这些需要深度思考的任务。

🌙

Moonshot/Kimi

擅长联网搜索。当需要查询最新信息时使用，弥补其他模型无法联网的短板。

前端：Vue 3 的响应式界面

前端是用户直接看到和操作的部分。它用 Vue 3 构建，核心思想是"数据变了，界面自动更新"。

frontend/src
api 所有 HTTP 请求在这里发出去
stores Pinia 状态管理——全局数据存在这里
pages 30+ 个页面组件
components 可复用的 UI 组件（编辑器、面板、弹窗）
router.js 页面路由——哪个 URL 显示哪个页面
🎨
富文本编辑器

系统用了两个编辑器：Tiptap（无头编辑器，高度可定制）和 WangEditor（开箱即用）。用户可以在编辑器里直接修改 AI 生成的文章，就像在 Word 里编辑一样。
