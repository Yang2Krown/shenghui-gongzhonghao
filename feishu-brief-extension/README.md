# 飞书 Brief 导入插件（POC）

这个扩展参考 [Cloud Document Converter](https://github.com/whale4113/cloud-document-converter) 的完整文档读取思路，但不依赖其下载流程，也不调用飞书 OpenAPI。

它只读取当前用户已经在浏览器中打开并有权限查看的飞书 Wiki/文档页面。标准 Docx/Wiki 页面优先从飞书页面内部的 block model 提取完整纯文字，页面 DOM 扫描只在内部模型不可用时兜底；用户点击发送后才通过网站页面桥接交给公众号智能体。

## 安装

1. 打开 Chrome 的 `chrome://extensions`。
2. 打开右上角“开发者模式”。
3. 点击“加载已解压的扩展程序”。
4. 选择本目录 `feishu-brief-extension`。
5. 如果扩展安装前已经打开飞书页面或网站，请刷新这两个页面。

## 使用

### 网站引导流程

在公众号智能体的「实操 / 商稿」页面，选择“飞书链接”，粘贴 Brief 链接并点击“打开并提取”：

1. 网站会在新标签页打开这份飞书 Wiki/文档，原来的创作页面保持不动。
2. 确认当前账号有阅读权限，并让 Brief 从顶部加载到末尾。
3. 点击浏览器右上角插件，点击“提取当前文档”，确认预览后点击“发送到网站”。
4. 插件会自动切回创作页面，网站校验文档链接后继续进行 Brief 结构化解析。

提取期间请勿离开、点击或刷新飞书页面；如果同时打开了多份 Brief，网站只接受刚才通过链接打开的那一份。

### 扩展弹窗

也可以在飞书文档标签页点击扩展图标：

1. 点击“提取当前文档”查看本地预览。
2. 确认后点击“发送到网站”。

提取结果会在弹窗右侧按 Markdown 形式预览；发送给网站时优先使用同一份 Markdown，仍保留 `rawText` 纯文字字段作为兼容兜底。

飞书列表节点的内部 `seq=auto` 会转换成 Markdown 的 `1.` 自动编号，不会把 `auto.` 当成正文显示。

## 支持的域名

- `*.feishu.cn`
- `*.feishu.net`
- `*.larkoffice.com`
- `*.larksuite.com`

网站桥接目前包含本地开发地址、服务器 IP 和 `https://gzh.midonghub.com`。如果网站是在插件安装前打开的，发送失败时插件会尝试补注入桥接脚本；仍建议先刷新网站页面。如果部署域名变化，需要同步修改 `manifest.json` 中的站点匹配规则，然后在 `chrome://extensions` 重新加载扩展。

## 隐私边界

- 不读取飞书 Cookie、Token 或密码。
- 不把正文发到第三方提取服务。
- 必须用户点击提取/发送，插件不会后台扫描文档。
- 插件优先读取飞书内部文档模型，因此不依赖用户当前停留在 Brief 的哪个位置；模型不可用时才会从顶部扫描到文档底部，等待虚拟滚动/懒加载稳定后合并正文。
- 只提取文字，不做图片下载、OCR 或图片识别；评论、隐藏内容、未加载的附件和被企业安全策略阻止的内容不保证可读。
